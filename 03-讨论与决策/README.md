# 讨论与决策记录规则

本目录用于追溯设计为什么这样决定，不作为完整聊天存档。02-设计基础维护当前有效输入；本目录保留讨论经过中的关键依据。日常讨论默认不落盘，只有用户明确要求保存时才按指定范围更新。

## 文件分工

| 位置 | 用途 | 维护边界 |
|---|---|---|
| 讨论记录/YYYY-MM-DD-主题.md | 阶段性讨论摘要，保留候选方向、取舍、结论和未决问题 | 同一阶段、同一主题优先汇总，不每轮问答另建文件；跨阶段的重要变更另记并关联前文 |
| [已确认决策.md](已确认决策.md) | 关键决策与重要变更的简要索引 | 记录日期、事项、理由或依据、适用范围及替代关系；详细需求和尺寸引用02，不重复维护整套设计输入 |
| [方案对比.md](方案对比.md) | 已保存候选方案之间的比较 | 注明方案及布局版本；候选意见不等于用户决定，结论获准保存后链接相应决策 |

## 哪些内容值得保存

- 阶段性讨论：本次要解决的问题、主要候选方向及利弊、已确认结论、尚未解决的问题。
- 关键决策：选了什么、选择理由、放弃其他方向的原因、日期及依据。未提供的理由注明未记录，不自行补全。
- 重要变更：原结论、新结论、变更依据、影响的需求或方案，以及替代关系。

重复问答、临时想法、工具操作过程和不影响设计的闲聊通常不保存。有参考价值的被否定方案保留简短否定理由即可。无需为了目录完整而补录全部历史会话。

## 阶段摘要的最小内容

按需要包含以下内容，不机械填满空项：

1. 日期、主题、讨论范围与来源。
2. 候选方向及关键取舍。
3. 用户已确认的结论和已提供的理由；明确区分助手建议。
4. 未决事项及其影响，注明需要用户选择还是技术核验。
5. 相关资料、方案版本及被替代记录的链接。

## 历史与当前状态

历史记录保留当时的回答，不随新决定重写。必要时在授权范围内追加“后续变更”说明，指向新的依据；不能仅凭文件较新就自行解决资料冲突。

用户要求“总结这轮讨论并记录”时，默认保存阶段摘要；不自动同步设计基础、决策索引或方案。需要同时更新时，以用户明确授权范围为准。记录缺失时标明缺失，不根据摘要重建原始会话或核验记录。
